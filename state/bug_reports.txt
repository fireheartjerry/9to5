## Identified Bugs

### BUG-001
Severity: CRITICAL
File: agents/verifier_runner.py
Line: 48
Status: Confirmed
Description: Brain-authored verify commands execute under shell=True with only partial sanitization. The metacharacter filter in sanitizeVerify is SKIPPED for matched `python -c` commands (m is not None path). A `python -c "safe_code" && evil_cmd` command where the body parses as valid Python AST would pass validation, and the trailing shell commands would execute via cmd.exe.
Fix: Use shell=False with shlex.split() for list-based invocation, or validate that nothing follows the closing quote of the -c argument in the sanitizer.

### BUG-002
Severity: CRITICAL
File: agents/verifier.py
Line: 153-162
Status: Confirmed
Description: buildContentScanVerify() interpolates f"{str(target_path)!r}" and f"{groups!r}" directly into a shell-executed Python one-liner. If target_path contains a single-quote character, Python repr() wraps it in double-quotes (e.g. repr("user's file") = '"user\'s file"'), which breaks the outer double-quote delimiter in the cmd.exe command. A crafted groups entry could also inject shell metacharacters.
Fix: Write the generated Python code to a temp file and invoke as `python tmpfile.py` to avoid shell quoting entirely.

### BUG-003
Severity: CRITICAL
File: state/task_io.py
Line: 90
Status: Confirmed
Description: TaskState.load(task_id) constructs `config.STATE_DIR / f"{task_id}.json"` without validating that task_id is a UUID or path-safe string. A task_id of "../../.env" resolves outside STATE_DIR. The Discord bot's /run slash command and the --resume CLI flag both accept user-supplied task_id values that flow directly into this path construction.
Fix: Validate task_id with re.fullmatch(r'[0-9a-f-]{36}', task_id) or uuid.UUID(task_id) before any filesystem construction in load(), _resumeRun(), and Discord command handlers.

### BUG-004
Severity: HIGH
File: agents/hooks.py
Line: 56
Status: Confirmed
Description: LOG_PATH = r"C:\9to5\logs\hooks.log" is a hardcoded Windows absolute path. The project supports worktrees and arbitrary install roots via config.PROJECT_ROOT, but this constant bypasses all of that. Under a git worktree or relocated install, logs go to the wrong location and the directory may not exist.
Fix: Derive from config: Path(config.LOG_DIR) / "hooks.log" or Path(__file__).resolve().parent.parent / "logs" / "hooks.log".

### BUG-005
Severity: HIGH
File: notifications/webdash.py
Line: 267
Status: Confirmed
Description: The CSRF check is `if self.token and self.headers.get("X-9to5-Token") != self.token`. When token is an empty string (falsy), the entire check is skipped and any HTTP POST to /api/control is unconditionally executed. Any process with localhost access can issue abort/pause/skip commands without authentication.
Fix: Always require the token: change to `if self.headers.get("X-9to5-Token") != self.token`. Treat empty token as "always reject".

### BUG-006
Severity: HIGH
File: agents/verifier_sanitize.py
Line: 100-107
Status: Confirmed
Description: The sanitizer's python -c regex match exempts matched commands from the metacharacter filter. A command like `python -c "safe_body"  && bad_command` where the closing double-quote appears mid-string would have the matched body extracted only up to the first `"`, leaving `&& bad_command` as unexamined trailing content that cmd.exe would execute.
Fix: After matching the python -c body, assert that the full cmd equals the matched portion only (no trailing content after the closing quote).

### BUG-007
Severity: HIGH
File: platform_core/runtime/control.py
Line: 296-304
Status: Confirmed
Description: drainOps() calls self.load() (non-strict, returns blank on unreadable) before overwriting the file. If the control file is transiently unreadable (Windows file lock contention), load() returns an empty bus (abort=False), and the subsequent _write() clobbers any queued abort or pause signal. The _mutate() method explicitly uses strict read mode (CB-5) to prevent exactly this, but drainOps does not.
Fix: Use self._readRaw(strict=True) inside drainOps, with CorruptBus handling, consistent with _mutate().

### BUG-008
Severity: HIGH
File: human_nature/continuity.py
Line: 50
Status: Confirmed
Description: Path(config.STATE_DIR) / task_id / "letters" builds a directory path with an unvalidated task_id, sharing the same path-traversal vulnerability as BUG-003. A task_id of "../../../arbitrary" would write to an arbitrary filesystem location.
Fix: Apply the same UUID validation as recommended in BUG-003 before constructing this path.

### BUG-009
Severity: MEDIUM
File: platform_core/orchestration/subtask.py
Line: 88-100
Status: Confirmed
Description: _repairVerify() scans the subtask description for .py paths and constructs {"cmd": f'python "{m}"'} with the raw match. This path originates from Ollama-authored description text and is interpolated into a shell command run via shell=True. A path containing `"` or shell metacharacters would cause injection.
Fix: Use shlex.quote() (POSIX) or the equivalent Windows quoting for the path. Ensure sanitizeVerify() is called on all repaired verifies before execution.

### BUG-010
Severity: MEDIUM
File: agents/executor_env.py
Line: 133-141
Status: Confirmed
Description: _DESTRUCTIVE_RE pattern uses `rm\s+-[rf]{2}\b` which requires exactly 2 flags from [rf] followed by a word boundary. This misses `rm -rfv`, `rm -rFvq`, and other common real-world variants where additional flags follow. The pattern diverges from DESTRUCTIVE_PATTERNS in action_risk.py (which uses substring matching and does catch these). This creates a defense-in-depth gap in prompt/output scanning via scanDestructive().
Fix: Align _DESTRUCTIVE_RE with DESTRUCTIVE_PATTERNS, or reuse the same taxonomy. Use `rm\s+.*-[rf]` or a broader character set.

### BUG-011
Severity: MEDIUM
File: config.py
Line: 108-123
Status: Confirmed
Description: _load_overrides() reads state/sie_overrides.json at import time and applies values directly as live config globals. Any local process that can write to the state directory can manipulate MAX_SUBTASK_ATTEMPTS, ADVERSARY_HEARTBEAT_EVERY, RETRIEVAL_K, etc. before 9TO5 starts. The file has no integrity check or signature.
Fix: Restrict write permissions on state/sie_overrides.json, or add an HMAC signature over the file content keyed on a secret from .env.

### BUG-012
Severity: MEDIUM
File: agents/hooks_selfmod.py
Line: 104-107
Status: Confirmed
Description: _resolveState() falls back to TaskState.loadLatest() when no task is pinned via env vars. In a concurrent or resumed run, the "latest" task may not be the currently-executing one, causing the guard to enforce the wrong task's hard_boundaries: blocking legitimate edits that aren't a boundary of the current run, or failing to block edits to files that ARE boundaries of the current run.
Fix: When no env vars are set and _envTaskRequested() returns False, exit 0 without loading any task, rather than guessing with loadLatest().

### BUG-013
Severity: MEDIUM
File: memory/obsidian.py
Line: 62, 207, 223, 257
Status: Confirmed
Description: Every requests call to the Obsidian local REST API uses verify=False (TLS certificate verification disabled) with urllib3.disable_warnings(). While localhost MITM is unlikely, this normalizes a pattern that would be dangerous if OBSIDIAN_BASE_URL is ever misconfigured to a non-loopback address, and suppresses warnings that would alert to misconfiguration.
Fix: Either provide a trusted local CA cert, or restrict the URL to 127.0.0.1 and document the tradeoff. Do not globally suppress TLS warnings.

### BUG-014
Severity: MEDIUM
File: platform_core/ops/external_project.py
Line: 33-56
Status: Confirmed
Description: cloneRepo(repo_url, ref) accepts any URL directly from the CLI (--repo-url) without validation. git clone can reach file:// URIs (reading local secrets), internal network services via git://, and arbitrary external hosts. This is an SSRF risk.
Fix: Validate repo_url against an allowlist or require https:// with known hosts. Reject file://, git://, and SSH URIs unless explicitly permitted. Validate ref against [A-Za-z0-9._/-].

### BUG-015
Severity: MEDIUM
File: agents/executor_env.py
Line: 133
Status: Confirmed
Description: DESTRUCTIVE_PATTERNS in action_risk.py uses "format " (with trailing space) as a simple substring match. A command like `python reformatter.py` contains the substring "format " at position in "reformatter", triggering a false-positive DESTRUCTIVE classification. This is overly conservative (blocks instead of allows), but could prevent legitimate reformat/reformatter operations from running.
Fix: Use word-boundary-anchored matching or require "format" to appear at command position rather than as an arbitrary substring.

### BUG-016
Severity: LOW
File: config.py
Line: 152-167
Status: Confirmed
Description: _configureLogging() is not thread-safe. The _LOGGER_CONFIGURED flag is checked and set without a lock. If two threads both import config and call getLogger() before either completes _configureLogging(), both threads pass the flag check and add duplicate FileHandler/StreamHandler to the "9to5" logger, causing every log message to be written twice.
Fix: Protect the _configureLogging body with a threading.Lock().

### BUG-017
Severity: LOW
File: memory/obsidian.py
Line: 53
Status: Confirmed
Description: atexit.register(lambda: _REST_POOL and _REST_POOL.shutdown(wait=True)) registers a new atexit handler every time _restPool() creates a new pool. If flushRest() is called and _REST_POOL is set to None, a subsequent _restPool() call creates another pool with a second atexit registration. Subsequent process exit calls shutdown() twice on different pool objects.
Fix: Track whether atexit has been registered and skip duplicate registration. Or capture the pool object: pool_ref = [pool]; atexit.register(lambda: pool_ref[0].shutdown(wait=True)).

### BUG-018
Severity: LOW
File: agents/elaborator.py
Line: 26
Status: Confirmed
Description: _REPO_CTX_CACHE: dict[str, str] = {} is a module-level dict shared across all tasks in a single process lifetime without invalidation. In a resilience-loop run with multiple tasks, a stale cached context from the first task (AGENTS.md + git log snapshot) is injected into all subsequent elaborations even after self-referential runs modify AGENTS.md.
Fix: Add a TTL or mtime check against AGENTS.md to detect staleness. Alternatively invalidate the cache at the start of each new task.
