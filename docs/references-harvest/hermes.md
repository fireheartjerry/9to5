# Hermes Agent — Harvest

## 1. Repo

- **Name:** Hermes Agent (`hermes-agent`, by Nous Research).
- **What it is:** A self-improving, multi-platform personal AI agent — a single agent loop reachable from CLI/TUI and a messaging gateway (Telegram/Discord/Slack/WhatsApp/Signal), with a closed learning loop (auto skill creation, memory curation), pluggable LLM providers, scheduled cron automations, and pluggable execution backends.
- **Maturity:** High / production. ~2.7k Python files, active issue numbers in the 40k+ range cited in code comments, full docs site, multi-language READMEs, packaging (uv/nix/docker), CI, native Windows + Termux support. Code is heavily battle-hardened (every module is dense with "issue #NNNNN" race/edge-case fixes).
- **Primary language:** Python (CLI/agent/tools); TypeScript for the desktop/web UI (`web/`, `apps/`).
- **License:** **MIT** (`LICENSE`, Copyright (c) 2025 Nous Research). Permissive — safe to port code.

## 2. Architecture sketch

- **One agent loop, many surfaces.** `run_agent.py::AIAgent` is the core tool-calling loop; CLI, gateway, desktop, ACP all drive the same loop. Slash commands and "modes" (MoA, compress, learn) decorate a turn rather than forking the loop.
- **Provider-agnostic LLM layer.** `agent/*_adapter.py` + `agent/auxiliary_client.call_llm` normalize Anthropic/OpenAI/Gemini/Bedrock/etc. wire formats behind one call; `hermes_cli/runtime_provider.resolve_runtime_provider` is the canonical provider→(api_mode, base_url, api_key) resolver reused everywhere (main loop, delegation, MoA).
- **Pluggable execution environments.** `tools/environments/` is a `BaseEnvironment` ABC with 6 backends: local, docker, ssh, singularity, modal, daytona. Unified spawn-per-call shell model with a captured session snapshot. This is the agent's "hands," swappable from local to isolated/serverless.
- **Subagent delegation.** `tools/delegate_tool.py` spawns isolated child `AIAgent`s (fresh context, restricted toolset, own terminal session); batch=parallel, `background=true`=async via a shared completion queue.
- **Closed learning loop.** Post-turn `agent/background_review.py` forks the agent to decide what memory/skills to persist; `agent/curator.py` maintains the skill collection over time; `/learn` (`agent/learn_prompt.py`) distills a conversation/dir/URL into a `SKILL.md`.
- **SQLite-backed state + recall.** Sessions/messages live in `hermes_state.py` with an **FTS5** index; `tools/session_search_tool.py` gives cross-session recall; `agent/insights.py` derives token/cost/tool analytics; `agent/verification_evidence.py` is a separate WAL ledger of what was actually proven.
- **Transparent infra the model never sees:** `tools/checkpoint_manager.py` (shadow-git snapshots + rollback), `agent/context_compressor.py` (auto context compaction), tool guardrails/approval, memory providers.

## 4. Top 3 takeaways

1. **Hermes is a goldmine for 9TO5's three weakest gaps (6, 3, 8) with portable MIT code.** `tools/environments/` (sandbox/isolation backends), `tools/checkpoint_manager.py` (dedup shadow-git snapshots + rollback), and `agent/context_compressor.py` (structured compaction with an anti-resume preamble and resolved/pending tracking) each map almost 1:1 onto a top-ranked 9TO5 gap and are self-contained enough to lift.
2. **Its standout edge is the *write-side* learning loop, which 9TO5 lacks entirely.** 9TO5 retrieves passively; Hermes forks the agent after each turn on a memory/skill-only tool whitelist to decide what to persist, then a curator maintains the skill set over time — all without touching the main prompt cache. That "forked reviewer on a restricted toolset" pattern is the single most transferable architectural idea.
3. **Verification is reframed as evidence, not assertion.** The passive `verification_evidence` WAL ledger + `verify_on_stop` guard record/require that a real check actually ran and passed before finishing — a concrete, cheap upgrade path for 9TO5's "marker present in source" verifies, and it doubles as the per-run proof trail the observability stack is missing.

---
**Highest-ranked single technique:** the **pluggable execution-environment backends** (`tools/environments/`) — a clean `BaseEnvironment` ABC with local/docker/ssh/singularity/modal/daytona implementations that would give 9TO5's Executor the sandboxed/isolated environment (gap 6) it currently has none of.
