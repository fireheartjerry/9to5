# CrewAI — Reference Harvest

## 1. Repo

- **Name:** CrewAI (`crewai-workspace`, uv monorepo under `lib/`).
- **What it is:** A production multi-agent orchestration framework where role-based "Agents" are grouped into "Crews" that run "Tasks" (sequential/hierarchical), plus a separate event-driven "Flows" engine for deterministic, persistable, branching pipelines.
- **Maturity:** High. Large, actively engineered codebase (crew.py ~2.4k lines, full RAG/memory/eval/telemetry subsystems), pre-commit, commitizen SCM versioning, A2A protocol support, MCP transports, enterprise hooks. One of the most-used Python agent frameworks.
- **Primary language:** Python (3.x, `from __future__ import annotations`, Pydantic v2 throughout).
- **License:** **MIT** — `Copyright (c) 2025 crewAI, Inc.` (`C:\9to5\references\crewai\LICENSE`). Permissive; ideas and code are freely portable.

## 2. Architecture sketch

- **Two execution models.** *Crews* = autonomous role-agents collaborating on Tasks (process = sequential or hierarchical-with-manager). *Flows* = a declarative, deterministic state machine (`@start`/`@listen`/`@router` + a serializable `FlowDefinition` of `code/tool/agent/crew/expression/each` actions) for when you want control, not autonomy. Flows can embed Crews as one action.
- **Task is the verification unit.** Each `Task` carries `guardrails` (callable or natural-language string → auto-wrapped LLM judge), `guardrail_max_retries`, and per-guardrail retry counters; output flows to the next task only after guardrails pass.
- **Pluggable everything via factory + registry seams.** RAG (`rag/factory.py` provider registry: chromadb/qdrant), flow persistence (`default_flow_persistence()`), memory storage backend, embeddings — all swap-in points with a built-in default and an override hook.
- **Unified Memory is a scoped semantic store.** Path-addressed (`/a/b/c`) vector memory with `MemoryScope`/`MemorySlice` views, composite scoring (semantic + recency-decay + importance), background async encoding, and an LLM-driven "deep recall" Flow.
- **First-class evaluation subsystem.** `experimental/evaluation/` has per-dimension LLM-judge evaluators (goal alignment, semantic quality, reasoning efficiency, tool selection/param/invocation) plus a dataset-driven `ExperimentRunner` regression harness with expected-score thresholds.
- **Event bus + telemetry spine.** `crewai_event_bus` emits typed events (`flow_events`, `llm_events`, `memory_*`, `checkpoint_events`, `agent_events`) consumed by listeners for tracing, eval display, and OTEL telemetry.
- **HITL is built into Flows.** `@human_feedback` pauses a flow (sync or async-via-provider, e.g. Slack), collapses freeform feedback into routed outcomes via an LLM `emit` set, and optionally *learns* (distills lessons into memory, pre-applies them next time).
- **Security primitives.** `security/fingerprint.py` (component identity) + `SecurityConfig`; flow script execution is disabled by default behind an env flag (capability-gate pattern).

## 4. Top 3 takeaways

1. **Steal the guardrail + evaluator stack to fix 9to5's #2 gap (shallow verification).** `LLMGuardrail` (NL-criterion → `{valid, feedback}` judge with bounded feedback-retry) plus the per-dimension `BaseEvaluator` rubrics and the dataset `ExperimentRunner` give 9to5 exactly the spec-vs-output LLM-judge + regression harness it lacks today, where verifies only assert markers are present. MIT-licensed and nearly drop-in onto the existing `_runAttemptLoop`/Verifier/Adversary.
2. **Flow persistence is the mid-subtask journal 9to5 is missing (gap #3), and `pending_feedback` is a durable gate.** Append-per-method WAL SQLite keyed by run id, resume-from-last-method, plus a `HumanFeedbackPending`→persist→`from_pending`→`resume` cycle, maps cleanly onto an ExecutionStep-level journal and a cross-process approval gate that survives a fresh process.
3. **Replace the O(n) cosine scan with the RAG factory + composite scoring (gap #4).** The provider-keyed `BaseClient` registry (Qdrant/Chroma ANN) behind a swap seam, the path-scoped `MemoryScope`/`MemorySlice` (a ready-made parallel-worker blackboard for gap #7), and recency-decay+importance composite ranking together address 9to5's memory scaling, code-RAG, and topology gaps at once.

---
**One-line summary:** CrewAI (MIT) is a mature dual-mode multi-agent framework whose guardrails, flow-state persistence, evaluation rubrics, and scoped ANN memory map directly onto 9to5's verification, durability, and memory gaps.

**Highest-ranked technique:** the **LLM-judge guardrail** (`tasks/llm_guardrail.py`) — a natural-language criterion auto-wrapped into a `{valid, feedback}` judge with bounded feedback-driven retry, the cleanest fix for 9to5's shallow "markers exist" verification.
