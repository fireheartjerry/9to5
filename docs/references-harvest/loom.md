## 2. Architecture sketch

- **Explicit event-driven agent state machine** (`loom-core`): `handle_event(event) -> action` is synchronous, pure, IoC — the caller performs all async I/O (LLM call, tool exec). States: `WaitingForUserInput → CallingLlm → ProcessingLlmResponse → ExecutingTools → PostToolsHook → (Error)`. Designed for determinism, exhaustive matching, and **replay**.
- **Trait-based tool system** (`loom-tools`): `Tool` trait (`name/description/input_schema/invoke`), `ToolRegistry`, JSON-Schema-validated args, workspace-root path-canonicalization security boundary, async invoke with progress reporting and per-tool `ToolExecutionStatus` (Pending→Running→Completed).
- **Server-side LLM proxy** (`loom-server-llm-*`): clients never hold API keys; all completions stream through `/proxy/{provider}/complete|stream` (Anthropic/OpenAI/Vertex/zai). Central place for retries, redaction, audit, cost.
- **Thread persistence** (`loom-thread`): offline-first local store (atomic temp+rename JSON, XDG dirs) + best-effort background sync to server with a **pending-sync retry queue**, optimistic concurrency (monotonic `version` + `If-Match`), UUID7 time-sortable IDs, SQLite-WAL server store, FTS5 search.
- **Weaver** (`loom-weaver*`, `loom-server-weaver`, `loom-k8s`): ephemeral, TTL-bounded, security-hardened **K8s pod sandboxes** for code execution; K8s is the sole source of truth; provisioned via REST or MCP.
- **eBPF audit sidecar** (`loom-weaver-ebpf*`, Aya): kernel-level syscall auditing of each sandbox (exec/file/net/privilege/**sandbox-escape**), batched to server, local buffer on disconnect, Prometheus metrics.
- **Spool** (`loom-common-spool`): a jj/Jujutsu fork as the agent's VCS — **operation log with full undo**, auto-stitch (auto-commit) per tool execution, conflict-aware.
- **Post-tool hooks** (`loom-auto-commit`): infra-level behavior (auto-commit, future auto-format/lint) that runs after mutating tools, invisible to the LLM, **fail-open**.
- Cross-cutting SaaS: ABAC auth, PostHog-style analytics, Sentry-style crash/symbolicate, feature flags/experiments/kill-switches, crons, SCIM, redact, webhooks — all with their own specs and a unified Svelte observability UI.

## 4. Top 3 takeaways

1. **The single biggest steal is "infra-level commit-per-mutating-tool as a step journal."** Loom's PostToolsHook auto-commit (plus the spool operation log) turns 9to5's missing mid-subtask checkpoint (Gap 3 — a top-3 brief priority) into a near-free byproduct: every `edit_file`/`bash` becomes a durable, individually-revertable commit, so a crash mid-attempt resumes from the last completed step and rollback is just a git/op-log undo — not a whole-subtask restart. It's fail-open and invisible to the model. Moderate port effort, very high payoff.

2. **Loom solves Gaps 5/6 (tracing + sandbox) at an infrastructure tier 9to5 has chosen not to build.** Weaver (ephemeral hardened K8s pods, K8s-as-truth, TTL cleanup) + the eBPF audit sidecar (syscall-level "what did it actually do," sandbox-escape detection) are the heavyweight but correct answers to "stop running `--dangerously-skip-permissions` on the real tree behind only regex guards." Even without adopting K8s/eBPF, the *concepts* — capability-scoped throwaway executor + semantic syscall audit + a single instrumented LLM proxy chokepoint for consistent cost/token series — are the right direction for 9to5's coarse hook-guard model.

3. **Several cheap, idea-only patterns are immediately applicable to 9to5's Python plumbing:** the offline-first + pending-retry-queue write pattern (crash-safe persistence for any best-effort external write), optimistic `version`/`If-Match` concurrency for the three-process state races, FTS5 keyword retrieval with trigger-maintained sync (a scalable complement to the O(n) cosine scan in Gap 4, indexing *solution content* not metadata), the `oracle` secondary-LLM-as-a-tool for in-loop debate (Gap 7), and treating post-edit lint/format/test as deterministic hooks rather than LLM-authored content-scan verifies (Gap 2).
