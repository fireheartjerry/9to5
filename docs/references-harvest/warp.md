# Harvest: warp

## 1. Repo

- **Name:** `warp` (warpdotdev/warp) — Warp, "an agentic development environment, born out of the terminal."
- **What it is:** The open-source client codebase for the Warp terminal, plus an unusually complete set of **agent-operations artifacts**: the spec corpus, skill library, and GitHub-Actions agent workflows that Warp's own coding agent ("Oz") uses to triage issues, write specs, implement changes, review PRs, and draft changelogs. The terminal itself is Rust; the harvest value is almost entirely in the markdown/agent layer.
- **Maturity:** Production. Real company product, 60+ crate Cargo workspace, live agentic OSS-management pipeline (build.warp.dev). OpenAI is the founding sponsor; agent workflows are GPT-powered.
- **Primary language:** Rust (workspace), with the agent layer in Markdown + small Python helper scripts + GitHub Actions YAML.
- **License:** Dual. `warpui_core` and `warpui` crates → **MIT** (`LICENSE-MIT`). Everything else → **AGPL v3** (`LICENSE-AGPL`). The agent/spec/skill markdown falls under AGPL — patterns are freely reusable, verbatim file copying is not.

## 2. Architecture sketch

- **Two-doc spec system** (`specs/<TICKET>/PRODUCT.md` + `TECH.md`, 231 ticket dirs): every feature is decomposed into an approved *product* spec (behavior, goals/non-goals, success criteria, validation) and a *tech* spec (relevant code with exact `file:line` anchors, current state, numbered proposed changes, end-to-end flow, phased implementation plan, risks+mitigations, testing). This is the agent's planning artifact.
- **Skill library** (`.agents/skills/`, `.warp/skills/`, plus an external `warpdotdev/common-skills` + `oz-for-oss` repo): each skill is a `SKILL.md` with frontmatter (`name`, `description`, optional `specializes` / `specializes_source`). Skills cover triage, dedupe, PR review, bug repro, changelog drafting, feature-flag add/remove, telemetry, onboarding verification, Rust unit tests.
- **Skill specialization (inheritance):** repo-local skills *specialize* a shared core skill, overriding only categories the parent declares overridable, and refuse to run unless the parent is installed. Shared skills are version-pinned via `skills-lock.json` (managed by `npx skills`).
- **Agent automation as reusable GH-Actions workflows** (`.github/workflows/`): issue triage, dedupe, PR review, changelog draft, and a cross-repo "docubot" all run as thin local workflows that `uses:` a shared external workflow and pass secrets through. Several run on **weekly cron to self-improve the skill files** from recent maintainer feedback.
- **Hybrid skill = prompt + deterministic scripts:** `changelog-draft` keeps LLM judgment (classification) in `SKILL.md` but pushes all data-gathering/conversion into bundled Python scripts ("do NOT generate this manually — always use the script so output is deterministic"), with a completeness invariant (every PR must land in `entries | skipped | needs_review`).
- **Multi-agent fan-out with bounded recursion:** `onboarding-verification-skill` launches a parent orchestrator → 2 baseline computer-use explorers → each *proposes* follow-up branch plans → parent dedups and launches a bounded (≤4) second wave; children are explicitly forbidden from recursing ("record as a later-run suggestion instead").
- **Feature-flag-gated rollout lanes:** every change is gated by a `FeatureFlag` with `DOGFOOD_FLAGS` / `PREVIEW_FLAGS` / `RELEASE_FLAGS` staged enablement, runtime check preferred over compile-time; specs treat "add the flag" as Phase 0.
- **Issue lifecycle state machine:** readiness labels `ready-to-spec` → `ready-to-implement` gate an issue from triage into the spec/implement pipeline, with explicit criteria for when an agent may apply each.

## 4. Top 3 takeaways

1. **The PRODUCT.md + TECH.md spec pair is the single most stealable thing here** and it lands squarely on 9to5's #1 gap. It is a concrete, battle-tested decomposition template that turns "plan a feature" into a reviewable artifact with goals/non-goals, success criteria, pre-resolved code anchors, a *phased* implementation plan, risks+mitigations, and an explicit testing/validation section. 9to5's architect/elaborator could emit this exact shape, and the phases double as resumable subtask boundaries (#3) and the validation section as a verification rubric (#2). It also demonstrates the issue→`ready-to-spec`→`ready-to-implement`→spec→PR lifecycle that maps onto 9to5's gate model.

2. **Warp operationalizes "skills as living, self-improving, governed assets"** in a way 9to5 has not: skill *inheritance* (`specializes` + overridable-categories + lock-pinned shared set), hybrid skills that split LLM judgment from deterministic scripts with checkable invariants, and—most notably—**weekly cron loops that rewrite the skill files from recent feedback**. That closes the loop between 9to5's experience ledger and its prompt/playbook registry (auto-tuning charters from run outcomes), which today is static champion/challenger only.

3. **The PR-review evidence gate and the bounded-fan-out orchestration are directly portable** to 9to5's two weakest spots. The review rubric's "user-visible change with no visual evidence ⇒ auto-REJECT, verdict=REJECT" is exactly the kind of semantic, non-token verification 9to5's verifier/adversary lacks. The onboarding skill's parent-orchestrator → baseline-explorers-propose-branches → bounded second wave (with an explicit no-self-recursion rule and a recursion budget) is a clean, safe multi-agent topology that avoids the shared-git-tree clobbering problem 9to5 hits under parallelism.

---

**One-line summary:** Warp's OSS repo is a goldmine of *agent-operations* patterns (spec templates, governed self-improving skills, review/triage rubrics, bounded multi-agent fan-out) wrapped around a Rust terminal — high fit for 9to5's planning/verification/multi-agent gaps.

**Highest-ranked single technique:** the **`PRODUCT.md` + `TECH.md` two-doc spec template** (`specs/APP-*/`) — a reviewable, phased, code-anchored decomposition artifact that fills 9to5's #1 planning gap and feeds #2 verification and #3 checkpointing for free.
