# Reference Harvest: Microsoft Agent Framework (MAF)

## 1. Repo

- **Name:** Microsoft Agent Framework (`agent-framework`, PyPI; `Microsoft.Agents.AI`, NuGet).
- **What it is:** Open, multi-language (Python + .NET) framework for building production-grade AI agents and **graph-based multi-agent workflows**, with first-class durability/checkpointing, OpenTelemetry observability, middleware, and human-in-the-loop. Successor unifying AutoGen + Semantic Kernel.
- **Maturity:** High / production-oriented and very actively developed by Microsoft. Large surface (dozens of provider sub-packages, AF Labs experimental tier, DevUI). Consistent typing, ADRs under `docs/decisions/`, design docs under `docs/design/`.
- **Primary language:** Python (harvested here) and C#/.NET (parallel implementation).
- **LICENSE:** **MIT** (`LICENSE`, "Copyright (c) Microsoft Corporation").

## 2. Architecture sketch

- **Pregel/superstep workflow engine** (`core/agent_framework/_workflows/`): a directed graph of `Executor` nodes connected by typed `Edge`s; execution proceeds in **supersteps** — all messages produced in step N are delivered together at step N+1. This is the orchestration substrate under all the higher-level patterns.
- **Two-phase shared state** (`_state.py` `State`): a `_committed` dict + a `_pending` write buffer; executors `set()` into pending, `commit()` flushes at superstep boundary, `discard()` rolls back. Functions as a transactional **blackboard** for concurrent workers.
- **Checkpointing at superstep boundaries** (`_checkpoint.py`, `_runner_context.py`): `WorkflowCheckpoint` snapshots committed state + in-flight messages + pending human-input events + iteration count, chained via `previous_checkpoint_id`, keyed to a `graph_signature_hash` for restore-compatibility validation. Pluggable `CheckpointStorage` Protocol (in-memory + atomic-write file backends). Enables pause/resume and **time-travel** (`restore_from_checkpoint`).
- **Request/response correlation for human-in-the-loop** (`_request_info_mixin.py`, `RunnerContext.add_request_info_event` / `send_request_info_response`): a workflow can emit a typed `request_info` event, the run pauses with that pending event *captured in the checkpoint*, and resumes when a typed response is injected — HITL that survives a crash.
- **High-level orchestration builders** (`packages/orchestrations/`): Sequential, Concurrent (fan-out/aggregate), Handoff (decentralized agent-chosen routing), GroupChat (orchestrator-directed), and **Magentic** (Magentic-One: task-ledger + progress-ledger planner). All compile down to the superstep graph.
- **Three-layer middleware** (`_middleware.py`): `AgentMiddleware`, `FunctionMiddleware` (per-tool-call), `ChatMiddleware` (per-LLM-call) pipelines with `next()` chaining, early **termination**, result override, and dynamic tool add/remove inside a call.
- **OpenTelemetry-native observability** (`observability.py`): emits spans + metrics under the OTel **`gen_ai.*` semantic conventions** (token usage counters, operation-duration histograms, tool spans, nested-usage accumulation), with W3C trace-context propagated *through workflow messages* for cross-executor span linking.
- **Long-horizon context compaction** (`_compaction.py`): a family of `CompactionStrategy` objects (truncation, sliding-window, tool-result, summarization, token-budget-composed) wired in as a `ContextProvider` that rewrites message history with provenance metadata.
- **Durable hosting** (`packages/durabletask/`): binds the workflow engine to Azure Durable Task / entities for externally-durable orchestration (durable agent state, orchestration context).

## 4. Top 3 takeaways

1. **The superstep + two-phase-commit-state + boundary-checkpoint trio is the single most transferable design, hitting three 9to5 gaps at once (#3 resume, #7 blackboard, and the substrate for #5 tracing).** 9to5's durability stops at subtask granularity and its parallel workers clobber one git tree; MAF shows a coherent answer — stage writes in a pending buffer, snapshot committed state + in-flight messages at deterministic boundaries, and resume by re-applying. The `graph_signature_hash` guard and atomic/safe-deserialization file storage are small, high-value details worth copying verbatim.

2. **Magentic-One's dual-ledger planner is the standout multi-agent technique and directly attacks 9to5's weakest layer (#1 planning, with bonus #2).** Instead of a one-shot JSON plan from a 7B brain, it maintains a structured *fact ledger* (given / to-look-up / to-derive / recalled) and re-evaluates a *progress ledger* every turn (satisfied? looping? progressing? who's next?), using a stall counter to trigger a root-cause-aware fact+plan rewrite. That is exactly the "decomposition-with-verification + reliable replan" 9to5's `_applyReplan` lacks — port the ledger schema even if not the full orchestrator.

3. **Adopt the OTel `gen_ai.*` semantic conventions wholesale for observability and cost (#5), and bolt on the middleware seam for tool policy (#6/2.6).** MAF emits standardized spans/metrics (token-usage counters, duration histograms, cache/reasoning token splits) with trace context propagated through messages for a true cross-run span tree — replacing 9to5's opportunistic `cost_usd` with a consistent metric series and enabling threshold alerting. The 3-layer middleware (agent/function/chat) with early-termination and dynamic-tool control gives 9to5 the per-tool-call interception layer it currently has no equivalent of.

---
**One-line summary:** MAF is a high-maturity, MIT-licensed superstep workflow engine whose checkpointing, two-phase shared state, Magentic dual-ledger planner, and OTel `gen_ai` observability map cleanly onto 9to5 gaps #1/#3/#5/#7/#8.

**Highest-ranked technique:** the **superstep-boundary checkpoint with two-phase-commit shared state** (`_workflows/_checkpoint.py` + `_state.py` + `_runner_context.py`) — one design that fills the mid-subtask resume gap (#3) and the shared-blackboard gap (#7) simultaneously.
