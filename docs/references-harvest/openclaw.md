# OpenClaw — harvest

## 1. Repo

- **Name:** OpenClaw (`openclaw`, v2026.6.10).
- **What it is:** A self-hosted, single-user **personal AI assistant gateway** — a multi-channel control plane (WhatsApp/Telegram/Slack/Discord/Signal/iMessage/… + WebChat, voice, live Canvas) that fronts a built-in coding/agent runtime. Effectively a Claude-Code-class agent harness wrapped in a messaging gateway, with a Docker-sandboxed executor.
- **Maturity:** High. Large, actively-released monorepo (~16k TS files), CI badges, 22 internal `packages/*`, native apps (iOS/Android/macOS), Dockerfile/fly/render deploy targets, dense test coverage (`.test.ts` beside nearly every module), formal SECURITY.md + security audit subsystem.
- **Primary language:** TypeScript (pnpm workspace monorepo, Node 22.19+/24).
- **License:** **MIT** — `LICENSE`, "Copyright (c) 2026 OpenClaw Foundation".

## 2. Architecture sketch

- **Gateway control plane vs. product split:** channels/ + gateway/ normalize every messaging surface into one session/turn model; the "assistant" (agent runtime) is a separate concern. Mirrors 9to5's strict-protocol / replaceable-intelligence split.
- **`packages/agent-core`** is the provider-agnostic agent loop: `agent-loop.ts` drives turn → stream assistant → execute tool calls → repeat, with steering/follow-up message injection, before/after tool hooks, deferred tool resolution, and per-turn model/thinking re-resolution.
- **`packages/llm-core` + `llm-runtime` + `model-catalog-core`** abstract providers; `packages/tool-call-repair` salvages model-emitted plain-text/Harmony/XML-ish tool calls into structured calls.
- **`src/agents/sandbox/`** is a full Docker-backed isolated executor: capability-scoped tool allow/deny policy, bind-mount/seccomp/apparmor/network validation, fs-bridge, prune/registry/ssh backends.
- **Context management** is a first-class subsystem: `src/agents/compaction*` + `harness/compaction` (hierarchical token-share summarization, branch summarization over a session tree) + `src/context-engine` (pluggable context transforms) + `agent-hooks/context-pruning`.
- **`src/trajectory/`** emits a versioned JSONL trace (runtime + transcript sources, parent/seq linkage) plus an export bundle manifest for offline replay/debugging.
- **`src/sessions/` + acp-core session tree** persist sessions as a branchable tree of typed entries (message / compaction / branch_summary / model_change / leaf), enabling branch navigation + resumable summaries.
- **`src/security/audit*`** is a standalone static/deep safety auditor (exec-safe-bins, deep code-safety probes, gateway exposure) over config and tool surfaces.

## 4. Top 3 takeaways

1. **Context compaction is OpenClaw's standout, directly-portable strength and 9to5's biggest open gap (#8).** The trio of (a) tool-pair-preserving token-share chunking with adaptive ratios, (b) a `MUST PRESERVE` structured summary contract, and (c) history pruning with orphan-tool-result repair is a complete, battle-tested long-horizon memory engine. `compaction-planning.ts` + `branch-summarization.ts` are near-drop-in references; even just porting the summary rubric upgrades 9to5's rolling run memory immediately.

2. **Capability-scoped tool policy + Docker sandbox validation answer 9to5's "sandboxed executor / per-subtask capability scoping" gap (#6) concretely.** `tool-policy.ts` (layered allow/deny with source provenance) and `validate-sandbox-security.ts` (credential/socket/symlink/seccomp/network threat model) are self-contained and give 9to5 a real isolation + per-subtask scoping design to replace `--dangerously-skip-permissions` on the live tree.

3. **The trajectory JSONL trace (#5) and tool-call-repair (brain-reliability) are high-value secondary lifts.** The versioned trace schema with parent/seq linkage + export manifest is the structured span tree 9to5's observability lacks; and plain-text/Harmony tool-call repair is a principled answer to the fallback-scaffolding tax 9to5 pays for unreliable local-7B JSON output.
