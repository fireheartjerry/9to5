# Reference Harvest: generative-agents

## 1. Repo

- **Name:** Generative Agents: Interactive Simulacra of Human Behavior (Stanford, Park et al., UIST '23; arXiv 2304.03442).
- **What it is:** Research code for "Smallville" — 25 LLM-driven agents living in a Django sandbox, each with a **memory stream + retrieval + reflection + recursive planning** cognitive loop. The famous origin of the recency/importance/relevance retrieval score and the reflection-tree idea.
- **Maturity:** Research artifact, not a library. Single-author style, debug `print`s everywhere, hardcoded constants, GPT-3.5/GPT-4 (`openai` legacy SDK `ChatCompletion`). Influential but not production-grade.
- **Primary language:** Python (backend cognition) + JavaScript/Django (frontend game/replay; out of scope).
- **License:** **Apache License 2.0** (`LICENSE`, root). Permissive — safe to port code with attribution.

## 2. Architecture sketch

- **Perceive → Retrieve → Plan → Reflect → Execute** loop per agent per tick (`persona/cognitive_modules/*.py`, orchestrated by `persona/persona.py::move`).
- **Memory stream** = append-only list of `ConceptNode`s (events/thoughts/chats) in `associative_memory.py`. Every node carries `created`, `last_accessed`, `poignancy` (importance), embedding key, SPO triple, keywords, and `filling` (parent node ids = provenance).
- **Retrieval** (`retrieve.py::new_retrieve`) scores every node by a weighted sum of three normalized signals — **recency** (exponential decay on `last_accessed`), **importance** (LLM-assigned poignancy 1–10), **relevance** (cosine of node embedding vs. focal-point embedding) — and returns the top-k.
- **Reflection** (`reflect.py`) triggers when accumulated importance crosses a threshold; the agent asks itself "what are the 3 most salient questions?", retrieves evidence, and synthesizes higher-level **thought** nodes that cite their source nodes (a recursive tree, `depth` field).
- **Planning** is hierarchical top-down decomposition: daily broad-strokes plan → hourly schedule → on-demand recursive task-decomp into ~5-15min sub-actions (`plan.py`), with **reactive re-planning** that splices a new action into the remaining schedule and re-derives the tail (`generate_new_decomp_schedule`).
- **Daily replan / identity revision** (`revise_identity`): at each new day the agent summarizes yesterday's retrieved memories into an updated "currently" status + fresh daily requirements before planning.
- **LLM-call harness** (`gpt_structure.py`): every structured call goes through a `safe_generate_response(prompt, repeat, fail_safe, func_validate, func_clean_up)` retry-validate-or-fallback wrapper — the exact pattern 9to5 hand-rolls everywhere.
- **Scratch** (`scratch.py`) holds tunable cognition hyperparameters (`recency_w`, `relevance_w`, `importance_w`, `recency_decay=0.99`, `att_bandwidth`, `retention`, `importance_trigger_max=150`).

## 4. Top 3 takeaways

1. **The retrieval score is the single highest-value steal.** 9to5's `memory/retrieval.py` already does the hard part (local embeddings + cosine over `experience.db`); swapping the bare cosine for **normalized recency·w₀ + importance·w₁ + relevance·w₂** is a small, idea-only change that immediately makes lesson injection surface *recent and high-stakes* failures instead of merely nearest-cosine metadata. Pair it with a write-time **poignancy/importance score** per subtask row.
2. **Reflection is 9to5's missing compaction primitive.** The importance-triggered "generate focal questions → retrieve evidence → write higher-level thought nodes that cite their sources" loop is exactly the hierarchical-summarization / long-horizon mechanism the brief flags as absent (gaps 2.3 + 2.9). Porting a periodic cross-run "lessons reflection" that distills raw subtask outcomes into a few cited, durable principles directly raises the structural context ceiling — and the `filling`/`depth` provenance gives auditable, traceable learned knowledge.
3. **Two cheap planning/robustness patterns transfer cleanly:** (a) **just-in-time hierarchical decomposition** (coarse blocks first, decompose only the next ~2h horizon, freeze the executed prefix and re-derive only the tail on replan) is a concrete antidote to the brittle one-shot 7B planner and greedy replan; (b) the **`safe_generate_response` validate-or-fallback harness** is the clean, reusable shape for the fallback scaffolding 9to5 currently hand-rolls per call site. Caveat: all LLM glue is legacy `openai.ChatCompletion` and would be reimplemented against 9to5's Ollama `llm_io`, not copied verbatim.

---
**One-line summary:** Stanford generative-agents (Apache-2.0) is a goldmine for 9to5's memory/long-horizon gaps — its retrieval score, reflection loop, and just-in-time decomposition map straight onto documented weaknesses.
**Highest-ranked technique:** the **recency + importance + relevance weighted retrieval score** (`retrieve.py::new_retrieve`) — idea-only port that upgrades 9to5's pure-cosine lesson retrieval into salience-aware recall.
