# bernstein

## 1. Repo

- **Name:** Bernstein (`sipyourdrink-ltd/bernstein`, PyPI `bernstein`).
- **What it is:** A deterministic Python scheduler that runs a crew of CLI coding agents (Claude Code, Codex, Gemini CLI, + ~40 more) against one goal in **parallel git worktrees**, with an HMAC-signed audit chain over every scheduling decision, then merges only the code that passes lint/types/tests/cross-model review.
- **Maturity:** Very high. Shipping product (v2.2.x), PyPI + GHCR + Homebrew + Docker, mkdocs/readthedocs site, OpenSSF Scorecard, CodeQL, semgrep/bandit baselines, devcontainer, release-please, SWE-bench harness, hundreds of modules with strict typing (`pyrightconfig.strict`). Far more mature/larger than 9TO5.
- **Primary language:** Python 3.12+ (async, dataclasses, StrEnum). FastAPI task server, Click CLI, Textual TUI.
- **License:** **Apache License 2.0** (verified in `LICENSE`). Solo-maintained.

This is the single most architecturally-aligned reference for 9TO5 seen so far: it is *also* a multi-agent coding-task orchestrator with a deliberate "deterministic scheduler / replaceable intelligence" split (zero LLM in the coordination loop), the same philosophy 9TO5 states in `docs/ARCHITECTURE.md`.

## 2. Architecture sketch

- **Deterministic scheduler, LLM only at the edges.** One LLM call decomposes the goal; everything after (who runs, where, with what budget, retries) is plain Python. "Replay yesterday's plan, get yesterday's task graph." Same thesis as 9TO5 but executed at much larger scale.
- **File-based state under `.sdd/`** (backlog open/claimed/closed YAML specs, runtime PIDs/logs, JSONL metrics, JSONL traces, agent catalog). Bearer-token FastAPI **task server** is the source of truth; manager + workers POST/GET tasks over HTTP.
- **Parallel isolation by git worktree per agent**, plus a pluggable **sandbox backend** abstraction (worktree / Docker / E2B / Modal / Cloudflare) behind one `SandboxSession` protocol. A **merge queue** serialises landings.
- **44 CLI adapters** behind a uniform `base.py` contract + capability checker + conformance suite; per-adapter cache-control, MCP loading, exit-code mapping, env isolation, credential scoping.
- **Heavy security/audit surface:** HMAC-SHA256 audit chain (RFC 2104), signed agent cards (detached JWS over JCS, Ed25519), per-artefact **lineage** (Sigstore-style transparency log: every file write → producer + inputs + prompt SHA + model + cost).
- **Self-evolution engine** (`evolution/`): EWMA/CUSUM/BOCPD change-point detection, Goodhart defenses, risk-stratified approval gates, sandbox-validated self-upgrade proposals with hash-locked invariants.
- **Full eval harness** (`eval/`): LLM judge, failure taxonomy, golden suites, calibration/Brier, incident→regression synthesis, A/B prompt runner, SWE-bench.
- **Rich observability:** OTLP/Prometheus/Datadog exporters, circuit breakers, decision log, postmortem, predictive alerts, per-call cost meter, SLO tracking.

## 4. Top 3 takeaways

1. **Bernstein is 9TO5's mature twin — mine it deliberately.** Same "deterministic scheduler, LLM at the edges, parallel coding agents, file-based state" thesis, but years ahead on planning validation, eval, isolation, and provenance. Several modules are small, self-contained, Apache-2.0, and nearly drop-in (whiteboard, judge, taxonomy, vertical-slice, compaction tiers, replay gateway).
2. **The biggest 9TO5 wins are cheap, deterministic gates around the weak brain — not a bigger brain.** The vertical-slice shape-check + corrective re-prompt (planning gap 1) and the rubric LLM judge (verification gap 2) both *raise output quality without trusting the 7B more*, which is precisely 9TO5's structural ceiling. These are the highest-leverage, lowest-effort ports.
3. **Bernstein already solved 9TO5's "concurrent workers clobber one tree" problem two ways:** per-agent git worktrees with a merge queue, plus an append-only role-scoped whiteboard for coordination — and a capability-scoped sandbox protocol whose `snapshot/resume` also addresses the mid-subtask checkpoint gap. Adopt the whiteboard first (smallest), the sandbox protocol later.

---

**One-line summary:** Bernstein is a far more mature, Apache-2.0, philosophically-identical multi-agent CLI-coding orchestrator that directly fills all 8 of 9TO5's gaps with small portable modules.

**Highest-ranked technique to steal:** the **vertical-slice plan shape-checker with corrective re-prompt** (`core/planning/vertical_slice.py` + `planner.py::_run_shape_check_with_retry`) — a deterministic post-LLM plan validator that re-prompts the brain once on structural violations, turning 9TO5's brittle one-shot 7B decomposition into reliable, reviewable task graphs without needing a stronger brain.
