# Reference Harvest: claude-code

## 1. Repo

- **Name:** `claude-code` (the leaked TypeScript source of Anthropic's official Claude Code CLI, internal codename **Tengu**).
- **What it is:** The full client implementation of the agentic coding CLI that 9TO5 already drives as its Executor — terminal REPL (React/Ink), ~40 tools, multi-agent coordinator, MCP host, hooks, SDK/headless mode, compaction, and memory.
- **Maturity:** Production. This is the shipping product reverse-recovered from a sourcemap leak (README dated 2026-03-31); code is dense, battle-tested, full of dated BQ/experiment notes.
- **Primary language:** TypeScript (Bun runtime; ~1,900 source files under `src/`).
- **LICENSE:** **No license file. Proprietary — © Anthropic PBC.** README states "All original source code is the proprietary property of Anthropic PBC ... educational and archival purposes only." Treat as **read-only / ideas-only**. Do **not** copy code verbatim into 9TO5; port *concepts* and re-implement.

> Note on relevance: 9TO5 consumes this exact binary. So the highest-value harvest is not "what to rebuild" but "which CLI features the brain/executor is not yet exploiting" (SDK control protocol, deferred-tool search, worktree isolation, coordinator mode, file-checkpointing, agent memory, the verification subagent) plus a few orchestration *patterns* worth lifting into 9TO5's own Python layer.

## 2. Architecture sketch

- **Entry → QueryEngine → Tool loop.** `main.tsx` (Commander + Ink) boots a REPL whose core is `QueryEngine.ts`/`query.ts`: an async generator that streams assistant turns, runs tool calls, and yields messages. Tools are uniform `ToolDef` objects (`Tool.ts`) with `inputSchema` (zod), `prompt()`, `isReadOnly`, `isConcurrencySafe`, `shouldDefer`.
- **Multi-agent via Task/Agent tools, not a separate planner.** `coordinator/coordinatorMode.ts` reframes the main loop as an orchestrator that spawns **workers** through `AgentTool` and continues them with `SendMessageTool`; results return as `<task-notification>` user-role messages. Subagents are forked queries (`tasks/`, `tools/AgentTool/runAgent.ts`, `forkSubagent.ts`, `resumeAgent.ts`).
- **Context management is layered.** `services/compact/` holds microcompact (cache-aware tool-result eviction), autocompact (threshold + circuit breaker), full structured summarization (`prompt.ts`), and an experimental file-backed session-memory compaction.
- **Durable memory is filesystem-first.** `services/autoDream/` consolidates session transcripts into `MEMORY.md` topic files; `tools/AgentTool/agentMemory.ts` gives each agent type a scoped persistent `MEMORY.md`; `services/extractMemories/` mines turns for durable facts.
- **Tool surface scales via deferral.** `tools/ToolSearchTool/` lets the model lazy-load tool *schemas* on demand (`select:` or keyword search), returning `tool_reference` blocks — so hundreds of MCP tools don't bloat the system prompt.
- **Isolation + checkpoints are built in.** `tools/EnterWorktreeTool/` switches a live session into an isolated git worktree; `utils/fileHistory.ts` + `commands/rewind/` snapshot every file edit (keyed by messageId) for instant rewind.
- **Headless/SDK is a first-class transport.** `cli/structuredIO.ts` + `cli/print.ts` implement an NDJSON stdin/stdout control protocol: `can_use_tool` permission callbacks, hook JSON output, elicitation, session-state events — the programmatic API surface 9TO5 currently does not use.
- **Stop hooks + cost telemetry close each turn.** `query/stopHooks.ts` runs turn-end gates that can *block continuation*, and fans out background work; `cost-tracker.ts` keeps per-model token/cost series wired to OTel counters and persists/restores them across resume.

## 4. Top 3 takeaways

1. **File-history checkpointing + worktree isolation together close 9TO5's two structural gaps (#3 and #6) with proven mechanics.** `utils/fileHistory.ts` snapshots every edit keyed to a message/step and restores on resume — a near drop-in design for a mid-subtask step journal so a killed attempt rewinds instead of restarting. `EnterWorktreeTool` shows per-session git-worktree isolation that would let parallel writers (and adversary remediation) stop clobbering one shared tree. These are concept-ports, not code-ports (TS→Python), but the designs are concrete.

2. **The verification subagent is the single most valuable artifact to lift.** `verificationAgent.ts` is a complete, adversarial, evidence-gated verifier prompt ("try to break it", per-change-type strategies, mandatory adversarial probe, anti-rationalization list, strict `VERDICT:` contract) — exactly the "deeper semantic verification" of gap #2, and far stronger than 9TO5's token-presence `buildContentScanVerify`. Pair it with `init-verifiers` (auto-generated, self-updating functional verifier skills) for behavioral UI/API/CLI checks.

3. **9TO5 is under-exploiting the CLI it already runs.** Deferred tools + ToolSearch, the SDK NDJSON control protocol (`can_use_tool` per-tool approval, hook JSON, elicitation), coordinator mode with a shared scratchpad, file-checkpointing flags (`CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING`), and agent persistent memory are all *configuration/feature* wins that need no reimplementation — just driving the executor differently. The structured 9-section compaction prompt is also directly portable to replace 9TO5's truncation-based context engineering (gap #8).

---

**One-line summary:** The leaked Claude Code source is a high-fit goldmine for 9TO5 (it *is* 9TO5's executor) — richest payoffs are file-history step-checkpointing, worktree isolation, the adversarial verification subagent, and structured compaction; many wins are just CLI features 9TO5 isn't using yet.

**Highest-ranked technique:** the **file-history snapshot + rewind** mechanic (`utils/fileHistory.ts`) — a per-edit, message-keyed transactional file journal that resumes from the last completed step, directly filling 9TO5's #3 gap (no mid-subtask checkpoint).
