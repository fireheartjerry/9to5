# Harvest: guild

## 1. Repo

- **Name:** The Agent Guild (`github.com/mathomhaus/guild`, binary `guild`).
- **What it is:** A single compiled Go binary that runs a first-class **MCP server backed by embedded SQLite**, giving any MCP client (Claude Code, Codex, Cursor) shared, persistent **task coordination ("quest")** and **agent memory ("lore")** across sessions and parallel agents. State is local-only under `~/.guild/`.
- **Maturity:** Production-shaped and unusually polished — goreleaser/Homebrew/install scripts, ADR references in comments, race-tested concurrency suite, `sqlcheck` static analyzer, migrations, golden tests. Solo/small-team OSS but engineered to a high bar.
- **Primary language:** Go 1.25 (pure-Go SQLite `modernc.org/sqlite`; ONNX embedder via `onnxruntime-purego`).
- **License:** **Apache-2.0** (confirmed in `LICENSE`).

## 2. Architecture sketch

- **Hexagonal core, MCP/CLI as thin surfaces.** `internal/lore` and `internal/quest` are transport-agnostic; `internal/mcp` (stdio JSON-RPC) and `internal/cli` (cobra) are adapters. Same code path for both so they cannot diverge.
- **Two primitives + two views.** Quest = a task on a board (priority, `depends_on`, files-touched, atomic claim, cascade-unblock). Lore = a typed knowledge entry (`observation|decision|research|principle|idea`). Oath = the `principle` subset auto-loaded each session. Brief = a handoff note for the next session.
- **Single bootstrap call.** `guild_session_start` sets active project and returns oath + last brief + top quest + parallel-safe candidates in one shot — the agent's entire operating context with no back-and-forth.
- **Hybrid retrieval.** `lore_appraise` runs a BM25/FTS5 lexical arm and an int8-quantized in-memory vector arm, fused by Reciprocal Rank Fusion (k=60), gated behind a vector-coverage threshold that degrades to BM25-only when the corpus isn't indexed yet.
- **Event-sourced quest state.** A quest's spec (subject/files/acceptance/deps) is reconstructed by replaying append-only `[spec]/[spec-replace]/[rework]` notes; `[checkpoint]` notes carry mid-task save-points.
- **Behavioral hint engine.** `internal/hints` fires nudges when an agent breaks the contract (e.g. no session-start, no brief at session end), then *measures whether the agent followed through* within N calls and persists hit/miss.
- **Embedded, agent-authored operating contract.** `internal/mcp/instructions.md` is a 16-rule discipline string delivered at MCP connect, with the project's live principles appended (prompt-cache-friendly: static prefix, principles tail).
- **Privacy-by-construction telemetry.** Usage logging accepts only non-content fields by function signature; atomic O_APPEND TSV under PIPE_BUF with rotation.

## 4. Top 3 takeaways

1. **Guild is a near-perfect reference for three of 9to5's top gaps at once (#3 checkpoint, #4 RAG, #7 topology), and it's Apache-2.0 Go you can read freely.** The standout trio to port in concept: **RRF hybrid retrieval** (`embed/rrf.go` + `appraise_rrf.go`) for gap #4, the **campfire `[checkpoint]` note** + **event-sourced spec replay** (`quest/campfire.go`, `quest/spec.go`) for gap #3, and the **atomic CAS claim + file-disjointness parallel-safety test** (`quest/accept.go`, `quest/bounties.go`) for gap #7. Each is small, self-contained, and dependency-light.

2. **The single highest-leverage steal is the parallel-safety rule paired with the atomic claim:** two subtasks may run concurrently iff their file-sets are disjoint AND neither depends on the other, and a one-statement `UPDATE ... WHERE status='next' AND claimed_by IS NULL` makes the claim race-free. This is exactly the missing piece that forces 9to5 to *disable adversary remediation under parallelism* (brief 2.4) — adopt it (plus per-worker git worktrees, gap #6) and concurrent workers stop clobbering one tree.

3. **Guild's most novel idea is the self-measuring hint engine** (`internal/hints`): it doesn't just nudge an agent toward correct discipline, it records whether the agent actually followed through within N calls and persists hit/miss — a built-in eval loop for prompt/guidance effectiveness. 9to5 has rich *presentation* observability but no mechanism that grades whether its own constitution/playbook guidance changes executor behavior; this pattern is worth lifting wholesale.

---

**One-line summary:** guild is an Apache-2.0 Go MCP server giving any agent shared SQLite-backed quest (tasks) + lore (memory) state, and it directly models 9to5 gaps #3/#4/#7 with clean, portable code.

**Highest-ranked technique:** the **atomic CAS quest-claim + file-disjointness parallel-safety detection** (`internal/quest/accept.go` + `internal/quest/bounties.go`) — the exact race-free claim and "no shared files, no dep conflict" test 9to5 needs to let parallel workers coexist instead of disabling remediation under parallelism.
