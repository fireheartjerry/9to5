# AGX — Harvest

## 1. Repo

- **Name:** AGX (`@mndrk/agx`), v2.4.11, by Mendrika Ramarlina.
- **What it is:** A local-first "workflow surface" for running coding agents (Claude / Codex / Gemini / Ollama) across tickets → implementation → PR → review, with human gates, checkpointed durable state, and a local web/desktop dashboard. Ships as CLI + Next.js board + Electron app from one npm monorepo.
- **Maturity:** Mature, actively shipped product (published to npm with download badges, PR-driven git history, telemetry, lock-tested command shapes). Not a research toy — production posture, but the v2 execution-graph runtime appears newer/partially wired (legacy execute/verify path still present; `v2TaskRouting` gates dispatch).
- **Primary language:** JavaScript/TypeScript (Node ≥22.16, uses native `node:sqlite`). Graph engine authored in `src/graph/*.ts` and compiled/mirrored to `lib/graph/*.js`.
- **License:** **MIT** (declared in `package.json` `"license": "MIT"` and README; no standalone LICENSE file shipped in this checkout).

## 2. Architecture sketch

- **Three layers (README):** State layer = SQLite WAL durable checkpoints; CLI + daemon = provider tool calls, filesystem edits, worktree isolation; Decision layer = human-gate transitions + review flow. Everything runs locally.
- **Typed execution DAG (v2):** `src/graph/` defines an `ExecutionGraph` of `work | gate | fork | join | conditional` nodes connected by `hard|soft` edges with `on_success|on_failure|always` conditions, plus an `ExecutionPolicy` (concurrency, replan/verify budgets, priority mode, node/graph timeouts) and explicit `DoneCriteria`.
- **Event-sourced graph runtime:** `GraphRuntime` drives the graph by enqueuing "tick" jobs onto a queue (`singletonKey` per graph), each tick advances ready nodes via the scheduler, persists with optimistic concurrency (`ifMatchGraphVersion`), appends node-status/budget events, and re-enqueues until the graph is terminal. Crash recovery re-enqueues all in-progress graphs on startup.
- **Legacy execute→verify loop:** `lib/cli/cloud/*` runs an iterative loop: execute (single agent or multi-provider **swarm**) → run local verify commands → an **LLM verifier/aggregator** emits a strict-JSON decision `{done, decision, next_prompt, …}` → feed `next_prompt` back, repeat to a max iteration.
- **Durable task state on disk:** per-task `checkpoints.json` (head + bounded history, ULID ids) with git patches stored as `patches/*.diff`; atomic writes with `.bak` backups; NDJSON append-only event logs; task-level file locks with PID-reuse guards.
- **Structured memory:** SQLite `agent_memory` table (WAL, versioned migrations, content-hash dedup); post-task LLM **extracts** 0–3 typed memories; task-start **injects** a budgeted "Past learnings" block scoped per project.
- **Safety/observability cross-cuts:** HMAC task signing + dangerous-pattern detector + JSON audit log (`security.js`); engine-call trace events with trace_id/duration/exit-code; budgeted prompt assembly that never auto-injects raw logs.

## 4. Top 3 takeaways

1. **The typed execution-graph engine (`src/graph/`) is the prize and maps straight onto 9to5's #1 and #7 gaps.** A small, dependency-free, well-typed DAG (work/gate/fork/join/conditional + hard/soft conditional edges + per-graph `ExecutionPolicy` budgets/timeouts + `DoneCriteria`), driven by an event-sourced, optimistic-concurrency, queue-tick runtime with crash recovery. This is exactly the "real task graph with dependencies, cost budgets, and replayable events" that 9to5's fallback-saturated one-shot 7B planner lacks. Even adopting only the schema + scheduler semantics (in Python) would be a major upgrade.

2. **Durable mid-task checkpointing + resume-prompt reconstruction directly fills 9to5's biggest durability hole (gap 3).** `checkpoints.js` snapshots plan/criteria/git-diff under a ULID with bounded history; `resume.js` rebuilds a compact, token-budgeted resume prompt with per-step `[x]/[→]/[!]` markers, current-step inference, and a "continue, don't restructure the plan" stability footer. Together they turn a kill mid-attempt into a step-level resume instead of 9to5's full-subtask restart — and the stability footer also curbs replan thrash.

3. **Verification and memory are both layered "deterministic/cheap first, LLM only for the semantic remainder."** The verify gate classifies criteria by regex and runs file/test/lint/typecheck checks before ever calling a model, with a separate verifier/aggregator LLM judging spec-vs-diff and emitting strict-JSON `next_prompt` feedback; memory extract/inject distills typed `decision/pattern/gotcha` lessons (actual content, per-project, hash-deduped) rather than 9to5's metadata-only lessons block. Both are modest ports that meaningfully deepen 9to5 gaps 2, 4, and 8.

---
**One-line summary:** AGX is a mature MIT-licensed local agent-workflow product whose newer `src/graph/` typed-DAG + event-sourced runtime, on-disk checkpoint/resume durability, and deterministic-first verify/memory layers are high-fit steals for 9to5's planning, durability, verification, and memory gaps.

**Highest-ranked technique:** the **typed execution-graph engine** (`src/graph/types.ts` + `scheduler.ts` + `runtime.ts` + `store.ts`) — a first-class work/gate/fork/join DAG with budget/timeout policy, driven by an optimistic-concurrency, event-sourced, crash-recovering tick runtime — the single best answer to 9to5's brittle one-shot planner (gap 1) and one-tree parallelism (gap 7).
