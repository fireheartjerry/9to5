# AutoGen — Harvest

## 1. Repo

- **Name:** AutoGen (`microsoft/autogen`)
- **What it is:** A layered framework for building multi-agent AI applications — event-driven agent runtime (Core), opinionated multi-agent team patterns (AgentChat), and pluggable extensions (model clients, code executors, memory, MCP). Also ships Magentic-One (a SOTA generalist agent team), AutoGen Studio (no-code GUI), and AgentBench.
- **Maturity:** Very mature but **now in maintenance mode** — Microsoft has moved active work to the successor "Agent Framework". Battle-tested, large community, clean typed codebase; no new features upstream. Ideas are still first-rate and stable.
- **Primary language:** Python (also a parallel .NET implementation under `dotnet/`).
- **License:** **Code = MIT** (`LICENSE-CODE`); **docs/content = CC-BY-4.0** (`LICENSE`). Code is freely portable with attribution.

## 2. Architecture sketch

- **Three layers.** `autogen-core` (message passing, event-driven `RoutedAgent`, single-threaded + gRPC-distributed runtime, topic/subscription pub-sub) → `autogen-agentchat` (opinionated team patterns) → `autogen-ext` (model clients, code executors, memory, tools/MCP).
- **Teams are "group chats"** managed by a `BaseGroupChatManager`. Concrete managers implement different orchestration topologies: `RoundRobin`, `Selector` (LLM/function picks next speaker), `Swarm` (handoff-routed), `GraphFlow` (DAG), and `MagenticOneOrchestrator` (ledger-driven).
- **Everything is `Component`-serializable.** Agents, teams, tools, termination conditions all have typed Pydantic config + `save_state`/`load_state`, so an entire team's mid-run state is a versioned JSON tree.
- **Magentic-One** = a default team (Orchestrator + WebSurfer + FileSurfer + Coder + ComputerTerminal) built on AgentChat; its orchestrator separates a **Task Ledger** (facts + plan, outer loop) from a **Progress Ledger** (per-step JSON judgments, inner loop).
- **Code execution is a pluggable `CodeExecutor`** with local, Docker, Docker-Jupyter, and Azure-Container backends — sandboxing is a first-class swappable surface.
- **Memory is a pluggable `Memory` protocol** (`update_context` injects into model context each turn); implementations include ChromaDB, Redis, mem0, Canvas, and the experimental task-centric memory bank.
- **Observability via OpenTelemetry** GenAI semantic-convention spans emitted from the core runtime for agent-create/invoke, chat, and tool-execute operations.

## 4. Top 3 takeaways

1. **Steal the Magentic-One dual-ledger orchestration (rank 5).** The Task-Ledger (facts: given/lookup/derive/guess + plan) vs Progress-Ledger (per-step JSON: satisfied? in-loop? progress? next? instruction) split, with a stall counter that triggers a root-cause-driven outer-loop replan, is a near-perfect fit for 9to5's #1 gap. The prompts (`_prompts.py`) are copy-pasteable and the JSON-retry ladder directly hardens 9to5's weak-7B planner. This single pattern upgrades planning *and* self-correction (gaps 2.1 + 2.5).
2. **Two memory/RAG wins are low-effort and scale-fixing.** The ChromaDB `StringSimilarityMap` (~120 lines) is a drop-in cure for 9to5's O(n) cosine scan, and the task-centric memory controller's failure→advice→validated-insight loop with LLM-filtered retrieval is exactly the "store solution content, not metadata" upgrade 9to5's lessons block needs.
3. **GraphFlow + Docker executor + OTel spans cover three more gaps cleanly.** GraphFlow gives real conditional task DAGs with all/any joins and cycle-exit validation (planning); the Docker `CodeExecutor` is a ready sandbox reference (tool-use); and the OpenTelemetry GenAI span helpers give the structured trace tree 9to5's observability stack lacks. Caveat: AutoGen is async/event-bus heavy and in maintenance mode — harvest the *patterns and prompts*, not the runtime wholesale.

---

**One-line summary:** AutoGen is a mature (now maintenance-mode), MIT-licensed multi-agent framework whose Magentic-One ledger orchestrator, ChromaDB memory, GraphFlow DAG, Docker sandbox, and OTel tracing each map onto a distinct 9to5 gap.

**Highest-ranked technique:** the **Magentic-One dual-ledger orchestrator** (Task Ledger + Progress Ledger + stall-triggered root-cause replan) — directly replaces 9to5's brittle one-shot 7B planner and adds principled loop/stall detection.
