# 9TO5 Modularity Rules

## Size thresholds (enforced by `tools/size_audit.py`)

| Bucket | Files | Functions |
|---|---|---|
| ideal | ≤300 lines | ≤25 lines |
| acceptable | 301–450 lines | 26–70 lines |
| must_split | >450 lines | >70 lines |

Run `python tools/size_audit.py` to check. Zero `must_split` violations required before commit.

## Splitting patterns

### Large class → mixin files
When a class has many methods that push the file over 450 lines, extract logical groups into
mixin classes in separate files. The original file imports and inherits from all mixins.

Example: `orchestrator.py` → `orchestrator_*_mixin.py` (7 mixins + 3 helper modules).

### Large module → sub-modules + re-export facade
When a module has many unrelated functions, extract by domain into `{module}_{domain}.py`.
Keep the original as a thin facade that re-exports all public names:

```python
from module_domain_a import funcA, funcB
from module_domain_b import funcC, funcD
__all__ = ["funcA", "funcB", "funcC", "funcD"]
```

Callers using `from module import X` continue to work unchanged.

### Large function → private sub-functions
When a single function exceeds 70 lines, extract coherent blocks into `_helper()` functions
in the same file. The public function becomes a thin coordinator calling the helpers.

## What not to do

- Do NOT change public API of re-export facades — callers must not break.
- Do NOT create circular imports — sub-modules must NOT import from their facade.
- Do NOT duplicate business logic across the split files — each split file owns its domain.
- Do NOT split test files just to hit size targets if it would break test isolation.

## Module doc header (required for all new modules)

```python
"""<One-line description>.

@AI-MAP v1  (generated by tools/repo_map.py -- edit SIDE-EFFECTS only, then regenerate)
EXPORTS:
  <symbol>(<params>) -- <description>
DEPENDS-ON: <imports>
SIDE-EFFECTS: unannotated
RUN/TEST: (no mapped test)
"""
from __future__ import annotations
```

After creating or renaming modules, run `python tools/repo_map.py` to regenerate `AGENTS.md`.
