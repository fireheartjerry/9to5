# Pattern: Skill-as-Design-Knowledge

## Core Mechanism
Capture what worked as a durable, reusable design-knowledge artifact (a markdown skill/pattern
doc constructed through interaction), not just as executable code. Future runs read the
accumulated knowledge to act better, turning one-off discoveries into compounding capability.

## When It Applies
The system re-learns the same lessons; useful discoveries evaporate after a run; you want
knowledge that generalizes across tasks, not a single frozen function.

## Transfer Recipe
When an invention verifies, distill it into a design-knowledge entry (mechanism, when-to-use,
transfer recipe, verification) and store it where finders can retrieve it next time. This is
how the invention corpus itself should grow — self-refreshing from shipped wins.

## Anti-Patterns
Storing raw diffs with no generalization (not reusable). Unbounded knowledge with no relevance
retrieval (context bloat). Treating captured knowledge as authority instead of adaptable prior.

## Example Candidate Shape
A post-verification step that writes a new invention_corpus card from a shipped innovation, so
the finders' prior art compounds run over run.

## Verification
A shipped invention produces a retrievable card; a later run on a related goal retrieves it and
its content shifts the proposal.
